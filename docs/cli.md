# zapret-hub-cli

`zapret-hub-cli.exe` — командная строка для работающего Zapret Hub. Она сделана для ИИ-агентов (Claude Code
и другие) и скриптов: каждая команда печатает один JSON-документ, коды выхода постоянные.

## Как это устроено

CLI прав администратора не просит и сам в системе делает только одно: `start` запускает задачу автозапуска
приложения (раздел «Если приложение не запущено»). Остальные команды он передаёт работающему приложению через
локальный канал `\\.\pipe\zapret-hub-cli`. Приложение уже запущено с правами и выполняет
команду тем же кодом, что кнопки окна: через ту же очередь операций, со снимком для отката. Поэтому окно и трей
сразу показывают, что сделал агент, а тексты ошибок у CLI и окна одни и те же.

Каждая команда попадает в журнал приложения `data\logs\ГГГГ-ММ-ДД.log`: `cli: apply_strategy: ok` или
`cli: apply_strategy: <текст ошибки>`. Команды, которые приложение не выполняло, — строкой
`cli: refused: <причина>`. Ожидание прогона (`tests wait`, `tests run --wait`) спрашивает приложение раз в 2 с,
и каждый вопрос — строка `cli: tests_status: ok`; ожидание диагностики (`diag run --wait`) — `cli: diag_status: ok`.

Версия протокола — 5 (`version` печатает её в поле `protocol`); с группой `diag` протокол вырос с 4: CLI и приложение
других версий друг друга отклоняют (код 3). Обновляйте `zapret-hub-cli.exe` и `zapret-hub.exe` вместе.

Если агент прервёт CLI посреди долгой команды (применение стратегии, исправление, загрузка), приложение
доведёт её до конца. Итог покажет следующий `zapret-hub-cli status`.

## Как включить

По умолчанию CLI выключен. Включите его один раз: «Настройки» → «Командная строка» → флажок «Управление из
командной строки (zapret-hub-cli)» → «Сохранить». Переключение действует сразу, без перезапуска.

Пока флажок выключен, приложение отвечает на любую команду отказом
`the CLI is off: enable it in Zapret Hub → Settings` (код 3). Выключить CLI можно и из него самого
(`settings set cli_enabled false`), включить — только в окне.

Канал принимает команды от пользователя Windows, который запустил Zapret Hub, а также от SYSTEM и
администраторов. Программы других пользователей и подключения по сети в канал не пускаются; программы из
песочниц (низкий уровень целостности) не могут ни писать в канал, ни читать из него.

Включённый CLI даёт любой программе, запущенной от вашего имени, те же действия, что окно: удаление службы,
правку `hosts`, свои стратегии. Текст своей стратегии zapret2 содержит `--lua-init`, то есть Lua-код. Любая программа от вашего
имени с включённым CLI может выполнить произвольный Lua-код от администратора одним `zapret2 validate` (проверка
запускает `winws2` с `--intercept=0`, а `--lua-init` грузит Lua из текста) и от SYSTEM через `zapret2 save` и
`apply` (служба zapret2). Лишнего риска нет, только если папка zapret2 и так доступна этой программе на запись
(обычно так, когда папка в вашем профиле): тогда она меняет сам `winws2.exe` и его Lua. Иначе включайте CLI, только
если доверяете каждой запускаемой программе. Папку zapret2, а с ней и то, какой `winws2.exe` запускает служба,
CLI не меняет: её меняют только в окне.

## Вывод и коды выхода

stdout — один JSON-документ с отступами, в UTF-8. При успехе это данные команды, при ошибке —
`{"error": "…"}` с полным текстом ошибки. Исключение — `tests report`: он печатает текст отчёта.
Команда, которой нечего вернуть (`zapret2 validate`, `zapret2 save`, `tests cancel` и т. п.), печатает
`{"ok": true}`. Ход (`tests wait`, `tests run --wait`) идёт в stderr,
в stdout — только итоговый JSON.
Порядок ключей в объектах не значим.

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | приложение выполнило команду с ошибкой, или прогон тестов завершился ошибкой |
| 2 | ошибка в аргументах или нет `--yes`: CLI отклонил команду сам, ничего не изменено |
| 3 | приложение недоступно или отказало, команда не выполнялась: не запущено, CLI выключен, канал занят дольше 10 с, версии CLI и приложения не совпадают. Исключение: ``Zapret Hub closed the connection without a full answer, so the command may have run: check with `zapret-hub-cli status` `` — команда могла выполниться |
| 4 | `tests wait`, `tests run --wait` или `diag run --wait` упёрлись в `--timeout` |

Код 0 значит, что команда выполнена, а не что проверка прошла: `apply`, `apply-best`, `restart`, `quick-check`
(и `zapret2 save` активной стратегии) печатают итог быстрой проверки, `proxy check` — итог проверки прокси, и
код у них 0 при любом итоге. Читайте поле `ok`: `"ok": false` — проверка не прошла.

Код 3 значит «чинить окружение, а не команду»: запустить приложение, включить CLI, обновить `zapret-hub.exe`
и `zapret-hub-cli.exe` вместе. Исключение — канал, закрытый без полного ответа: команда могла выполниться,
поэтому сначала `zapret-hub-cli status`, а не повтор вслепую.

Код 2 значит, что ничего не изменено, но не всегда, что в приложение ничего не ушло: `proxy check` без адреса
сначала читает настройки и только потом отказывает, если `socks5` не задан. Сам CLI проверяет только форму
команды: аргументы, значения из списков, `true`/`false`, `--yes`. Остальное — адрес в
`settings set socks5`, имена стратегий, текст своей стратегии — проверяет приложение, и его отказ — код 1.

`zapret-hub-cli --help` и `zapret-hub-cli <команда> --help` перечисляют команды и аргументы.

PowerShell читает вывод программ в кодировке `[Console]::OutputEncoding`. Чтобы кириллица в JSON не
испортилась, выполните перед вызовами `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.

`zapret-hub.toml` (`start_minimized`). Стратегии называются `zapret2:<имя>`, например `zapret2:general` или
`"zapret2:general (ALT11)"` (раздел «Стратегии zapret2»).

- `check_zapret2_folder` — открыл бы путь, переданный клиентом, и запустил бы из него `winws2.exe`, а папку
  zapret2 CLI не меняет (раздел «Настройки»);
- `take_notices` — забрал бы уведомления у окна;
- `open_tg_proxy` — открывает ссылку `tg://proxy` в Telegram; CLI печатает ссылку в `tg-ws status`;
- `test_live` — его заменяет `tests status`, а `diag_live` — `diag status`;
- `validate_route`, `import_route_lines` — проверка и импорт строк в редакторе правила окна.

## Настройки

`settings set <key> <value>` читает все настройки, меняет одну и сохраняет их, как кнопка «Сохранить» в окне:
приложение проверяет адрес прокси, включает или выключает автозапуск. Окно сразу показывает
новые значения: открытая вкладка «Настройки» следует за ними, пока вы в ней ничего не правили. Если правка
уже есть, вкладка оставляет вашу копию, и «Сохранить» запишет её поверх изменений агента.

| Ключ | Значение |
|---|---|
| `socks5` | `адрес:порт`, например `127.0.0.1:2080`; `""` — без прокси (в Windows PowerShell 5.1 — `'""'`, см. ниже) |
| `autostart` | `true` или `false` |
| `start_minimized` | `true` или `false`: при автозапуске оставаться в трее |
| `theme` | `system`, `light` или `dark` |
| `cli_enabled` | `false` выключает CLI; включить его из CLI нельзя |
| `diag_observe_secs` | целое от 10 до 120: сколько секунд диагностика наблюдает за программой; иначе код 2 |
| `diag_budget_min` | целое от 1 до 60: сколько минут диагностика пробует пути; иначе код 2 |
| `nekobox_dir` | папка NekoBox или NekoRay; `""` — очистить (в PowerShell 5.1 — `'""'`) |
| `game_filter` | `true` или `false`: встроенные стратегии обходят и порты 1024–65535 (`%GameFilter%`); активная стратегия ставится заново |

Папку zapret2 (`zapret2_dir`) CLI не меняет: служба zapret2 запускает из неё `winws2.exe` от SYSTEM, поэтому
папку меняют только в окне («Настройки» → «Папка zapret2» → «Сохранить»). `settings get` её показывает, а
`settings set zapret2_dir …` — неизвестный ключ, код 2. По той же причине скачать релиз zapret2
(«Скачать последний релиз…») можно только в окне: у CLI такой команды нет.

Сохранение через CLI не может включить `cli_enabled`: если вы выключили его в окне, пока команда читала и
сохраняла настройки, он остаётся выключенным. Если за это время вы сменили в окне папку zapret2,
приложение отклонит сохранение CLI ошибкой
`the zapret2 folder can be changed only in the Zapret Hub window (Settings)` (код 1): повторите команду.

Неизвестный ключ, не `true`/`false` у флажка или тема не из списка — код 2 со списком допустимых, до обращения
к приложению. Адрес `socks5` проверяет приложение: неверный — код 1 с его ошибкой
(`… is not an address like 127.0.0.1:2080`), настройки не меняются.

```
zapret-hub-cli settings set socks5 127.0.0.1:2080
zapret-hub-cli settings set socks5 ""
```

Windows PowerShell 5.1 не передаёт программам пустой аргумент: `""` пропадает, и CLI отвечает кодом 2, будто
значения нет. В нём пишите `'""'`:

```
zapret-hub-cli settings set socks5 '""'
```

## Маршруты

Правила маршрутизации через SOCKS5 (`data\routes.toml`). `routes add` и `routes edit` берут файл с таблицей
`[rule]` без `name`: имя — аргумент команды. `-` — stdin.

```toml
[rule]
enabled = true
protocol = "udp"                  # "tcp" | "udp" | "both"
ports = ["19294-19344", "50000-65535"]
ips = ["104.29.0.0/16", "35.217.0.0/16"]
domains = ["discord.media"]
```

`routes add mine --file rule.toml`. CLI проверяет файл до отправки (поля, подсети, порты, домены, программы
`apps`) и при ошибке выходит с кодом 2 и текстом с номером строки; приложению такой файл не уходит.
`routes remove` без `--yes` — код 2. Битый `routes.toml` правка из CLI не перезаписывает: она отказывает, пока
файл не исправлен. Включённость самой маршрутизации — `router on|off`; `settings set` её не трогает.

## Тесты

`tests run` без имён запускает все стратегии из `strategies list` в их порядке, кроме строк с `error` (встроенные
копии Flowseal входят); с именами — только названные, в указанном порядке. `--dpi` — набор DPI вместо стандартного. `--repeats <N>` (1–5,
по умолчанию 1) — сколько раз проверить каждую стратегию: N полных проходов по списку подряд (сначала все
стратегии один раз, потом все ещё раз), прогон длится в N раз дольше. Без `--wait` команда возвращается сразу:

```json
{
  "repeats": 1,
  "started": true,
  "strategies": 22,
  "suite": "standard"
}
```

`tests wait` и `tests run --wait` раз в 2 с спрашивают приложение о прогоне и пишут ход в stderr, по строке на
стратегию (с повторами — на стратегию в каждом проходе, `pass 2/3: 3/22 zapret2:general (ALT2)`):

```
3/22 zapret2:general (ALT2)
```

Когда прогон закончится, stdout получает компактный рейтинг. Порядок — как в прогоне: он уже отсортирован,
лучшая стратегия первая. `score` — счёт стратегии целиком (`ok` из `total` проверок прошли, `median_ms` —
медианная задержка и другие поля, как в `tests show --full`). С повторами `score` — сумма проходов (`total` —
проверки всех проходов, `ok` — прошедшие из них), задержки — медиана медиан проходов; ошибка запуска в любом
проходе — ошибка стратегии (`pass 2 of 3: …`). Каждый проход отдельно — в `passes` стратегии в
`tests show --full`; без повторов `passes` пуст.

`tests show <id> --failures` печатает по стратегиям сводку каждой непрошедшей проверки по всем проходам:
`{"<стратегия>": {"<цель> <вид> <статус>": {"count": N, "sample_error": "<первая строка ошибки curl>"}}}`,
например `"YouTube Tls12 Error": {"count": 3, "sample_error": "curl: (28) Connection timed out"}`. Ошибка
запуска — ключ `launch_error`; у проверки DPI `sample_error` — её код. Стратегии без сбоев не попадают в вывод.

```
{
  "canceled": false,
  "id": "2026-10-11_10-00-00",
  "ranking": [
    {
      "launch_error": null,
      "name": "zapret2:general (ALT11)",
      "place": 1,
      "score": { "ok": 36, "total": 36, "median_ms": 184, … }
    },
    …
  ],
  "restore_error": null,
  "suite": "standard"
}
```

- `launch_error` не `null` — стратегия не запустилась, она в конце рейтинга. `restore_error` — после прогона
  что-то не вернулось на место, подробности в журнале. `canceled` — прогон отменён.
- Прогон завершился ошибкой (например, папка zapret не найдена) — `{"error": "…"}`, код 1.
- Прогона сейчас нет — печатается итог последнего с запуска приложения: его рейтинг или ошибка; если прогонов
  не было — `{"last": null}`.
- `--timeout <s>` ограничивает ожидание: по истечении — код 4, а прогон продолжается; ждите дальше `tests wait`.
- Во время прогона приложение не меняет zapret: `apply`, `restart` и другие команды, которые его меняют,
  отвечают ошибкой (код 1). `tests status` и `tests cancel` работают.

`tests status` печатает `{"testing": …, "live": …, "last": …}`: `live` — ход прогона, как его видит окно,
`last` — `{"run_id": "…"}` или `{"error": "…"}`.

Хранятся 50 последних прогонов: сохранение нового удаляет более старые файлы `data/tests/<id>.json`. Результат
стратегии, которую проверяли только в удалённом прогоне, из `strategies list` пропадает. На Linux прогон ставит одну
таблицу nftables с портами всех стратегий прогона (два вызова root на прогон) и снимает её до восстановления службы;
отказ root — ошибка прогона.

## Диагностика

`diag run` наблюдает за программой или профилем, находит виновников (адреса, которые не открываются), пробует для каждого
пути обхода и в конце всё откатывает. Нужен ровно один из `--profile <id>` (`diag profiles`) и `--app <exe>`. Встроенные профили: `discord`, `dbd`, `youtube`, `steam` (магазин, сообщество, загрузки),
`discord-stream` (демонстрация экрана в Discord).
`--observe` — 10–120 с, `--budget` — 1–60 мин; вне диапазона — код 2. Без них берутся настройки `diag_observe_secs` и
`diag_budget_min`. Режим по умолчанию — `auto`: все виновники проверяются без человека. Профиль, который проверяется только
вживую (Dead by Daylight, «любая программа»), в `auto` даёт итог «не проверяется автоматически: нужен режим „со мной“».

- Без `--wait` команда печатает `{"started": true, …}` и возвращается; ход — `diag status` (`{"live": …, "failed": …}`: `live` — `null`, когда не идёт; `failed` — почему упала последняя диагностика, иначе `null`).
- `--wait` опрашивает `diag_status` раз в 2 с, пишет ход в stderr (каждую смену шага один раз) и в конце печатает отчёт —
  тот же JSON, что `diag show`: компактный (см. ниже), а с `--full` — весь `Summary`. Виновники — одной строкой после наблюдения (`culprits: <ключ> (<протокол> <порты>), …`);
  каждый законченный путь — строкой `culprit 1 35.217.19.0/24 · path 5/36 Прокси точечно: работает, 3/3, 26 ms`
  (или `не работает, 0/3`), каждая законченная группа — строкой с лучшим путём. Остановленная диагностика тоже
  печатает отчёт (`stopped: true`). Если отчёта не появилось, код 1 и в `error` — причина сбоя (тот же текст, что в уведомлении приложения) или «canceled».
- Если ни одна программа профиля не запущена (только Windows: на Linux имена процессов другие), диагностика кончается сразу, без наблюдения: `verdict.code = not_reproducible`, `client.app = not_running`, в `next_steps` — `ask_user: Запустите <exe>` и команда повтора.
- Режим `ask`: на вопрос «Работает?» (в stderr один раз) отвечайте `diag answer yes|no|skip`. Выбор виновников —
  `diag choose <key>…`; пока окно приложения открыто, приложение ждёт выбор 120 с, потом проверяет всех. В `auto` выбор
  не ждётся.
- `diag cancel` отменяет и откатывает. `diag stop` во время наблюдения заканчивает его и переходит к виновникам; во
  время перебора — больше путей не пробует, откатывает и строит отчёт из проверенного: лучший путь, исправления,
  картины, системные проверки; `stopped: true`, вердикт начинается с «перебор остановлен: результаты по проверенным
  путям», перепроверка других профилей пропускается (предупреждение в `warnings`). `diag apply --yes` применяет исправление отчёта и, если оно меняло стратегию,
  печатает быструю проверку.
- Компактный отчёт (по умолчанию для `diag run --wait` и `diag show`; поля без значения не печатаются): `report_id`, `profile`, `status` (`done`/`stopped`/`canceled`/`budget_hit`), `duration_s`, `verdict {code, text}`, `confidence {level, why}`, `client`, `observed`, `culprits` (`key`, `proto`, `ports`, `fault {code, args}`, `route`, `tried`, `working`), `best_paths` (`culprit`, `path`, `source`, `ok` вида `3/3`, `median_ms`, `tried`, `working`), `fixes` (`i`, `kind`, `text`, `cli`, `warnings`), `evidence`, `checks` (только не `Ok`), `not_checked`, `missing` (коды источников: `neko_log`, `neko_routes`, `discord_log`), `coverage`, `context`, `changes`, `warnings` (не относящиеся к исправлению), `rollback_error`, `next_steps`. Нет текста стратегий, строк по путям, представителей потоков. `fixes[].cli` — точная команда `zapret-hub-cli diag apply <id> --fix <i> --yes`, `null` для `manual` и `turn_off`; порядок и `i` те же, что в отчёте. `next_steps` — команды и строки `ask_user: …` по порядку: применить исправление и проверить повторным `diag run --wait --timeout 590`; спросить пользователя и повторить; `settings set nekobox_dir <path>`; `checks fix <действие>` для непройденных системных проверок. На Linux потоки не наблюдаются (нет WinDivert): в `not_checked` факты с кодом `platform:linux` и аргументом `flows`, `dns` или `paths`, вердикт не выше `inconclusive` (кроме `not_reproducible`, `whitelist` и `live_only`: они из журналов, проб и профиля, а не из потоков), остаются системные проверки, пробы и журналы.
- В начале диагностика читает системные проверки (те же, что `checks`, только чтение): отчёт несёт их в
  `system_checks`, а каждая не `Ok` — ещё и строка в `explanations`. Без папки zapret список пуст.

## Проба

`probe discord.com` или `probe https://gateway.discord.gg` — одна живая проверка хоста через то, что фильтрует
сейчас (служба zapret2, если запущена). У приложения CLI берёт только папку zapret2 (`get_settings`) и правила
(`list_routes`), остальное делает сам; протокол не меняется.

- Хост — без схемы, порта, `user@` и точки в конце; URL проверок — как дан, а голое имя или `имя:порт` получают `https://`.
  Пустой или с пробелом — код 2.
- `dns` — адреса системного резолвера (`dns_error` — если не ответил).
- `lists` — файлы `<папка zapret2>/lists/*.txt`, которые берут хост (`list-*`: имя и его поддомены, `^имя` —
  только имя) или один из его IPv4 (`ipset-*`: адрес или подсеть). `exclude` в имени — исключение.
  `lists_error` — папка не задана или не открывается.
- `route` — первое включённое правило `routes.toml`, которое берёт имя, иначе один из адресов; `null` — никакое.
- `checks` — HTTP, TLS 1.2 и TLS 1.3 через curl (как в тестах), `ping_ms` — ICMP, `null` — не ответил. Все
  четыре идут разом: проба занимает не больше 4–5 с.
- Без `--json` печатает то же текстом, по строке на пункт.

## Исключения

То, что zapret2 не трогает. Встроенные стратегии читают два списка в `<папка zapret2>/lists`:
`list-exclude-user.txt` (`domains`: домен и его поддомены) и `ipset-exclude-user.txt` (`ips`: IPv4-адрес или
подсеть). `ports` — порты и диапазоны (`51413`, `6881-6889`), трафик которых не попадает в очередь nftables
движка; это действует только на Linux (там же процессы группы `zapret-bypass` идут мимо движка всегда), в Windows
порты хранятся, но не применяются. Порты лежат в настройках (`excluded_ports`), `settings set` их не меняет.

Сохранение не трогает файл, записи которого не изменились; в изменённом комментарии, пустые строки и оставшиеся
записи остаются на своих местах, удалённые записи убираются, новые дописываются в конец. Если списки или порты изменились и
стратегия zapret2 стоит службой, ставит её заново: движок читает списки при старте, а таблица nftables берёт порты. CLI проверяет значение до
запроса: домен из двух и более меток, адрес или подсеть `a.b.c.d/n`, порт 1–65535 или диапазон по возрастанию —
иначе код 2. `add` уже имеющегося и `remove` отсутствующего — код 1, ничего не пишется.

## TG WS Proxy

[tg-ws-proxy-rs](https://github.com/valnesfjord/tg-ws-proxy-rs) — локальный MTProto-прокси, который ведёт трафик
Telegram через WebSocket. `tg-ws install` скачивает сборку своей ОС из последнего релиза
(`tg-ws-proxy-x86_64-pc-windows-gnu.zip` или `tg-ws-proxy-x86_64-unknown-linux-musl.tar.gz`) в
`<данные>/tg-ws-proxy`; если в релизе её нет, `tg-ws status` пишет причину в `unavailable`. Архив сверяется с
`SHA256SUMS` релиза, а без него — с `digest` ассета из GitHub API; без контрольной суммы и при несовпадении
установка отказывает. Прокси слушает только
`127.0.0.1`; секрет — 32 hex-символа, создаётся один раз и хранится в настройках, поэтому ссылка
`tg://proxy?server=127.0.0.1&port=<порт>&secret=dd<секрет>` не меняется между запусками.

- Linux: юнит `systemd --user` `zapret-hub-tg-ws` (`~/.config/systemd/user`), без прав root; включённый
  прокси работает и без приложения, журнал — `journalctl --user -u zapret-hub-tg-ws`.
- Windows: дочерний процесс приложения в его job object: стартует вместе с приложением, если включён, и
  завершается вместе с ним. Журнал — `data\logs\tg-ws-proxy.log` (флаг `--log-file`).

`--args` — дополнительные флаги через пробел (например `--dc-ip 2:149.154.167.220`), кавычки не поддерживаются.
На Windows флаги меняются только в окне приложения: прокси там — дочерний процесс приложения с правами
администратора, а канал CLI доступен любой локальной программе (та же граница, что у папки zapret2). Через CLI
`--args` с другими флагами отклоняется; порт и секрет меняются.

## Рецепт: подобрать и применить лучшую стратегию

```
zapret-hub-cli start
zapret-hub-cli tests run --wait --timeout 540
zapret-hub-cli tests wait --timeout 540
zapret-hub-cli apply-best
zapret-hub-cli quick-check
```

1. `start` поднимает приложение, если оно не запущено (раздел «Если приложение не запущено»).
2. `tests run --wait` запускает стандартный набор по всем стратегиям и ждёт рейтинг. Около 4 с на стратегию
   (проверки цели идут параллельно): 22 встроенные стратегии zapret2 — около 2 минут. У агента с пределом времени на команду (у Claude Code — 10
   минут) `--timeout 540` оставляет запас. Код 4 — прогон ещё идёт: повторяйте `tests wait --timeout 540`, пока
   не будет 0 или 1.
3. `apply-best` ставит первую стратегию последнего завершённого стандартного прогона (не отменённого).
4. `quick-check` подтверждает, что zapret работает: `"ok": true`. Смотрите на поле, а не на код выхода: при
   `"ok": false` он тоже 0.

## Файлы и stdin

Команды `zapret2 validate|save` читают файл или stdin (`-`). Допускаются UTF-8 и UTF-16LE;
BOM UTF-8 (Блокнот, `Set-Content -Encoding UTF8`) и BOM UTF-16LE (`>` и `Out-File` в Windows PowerShell 5.1) снимаются.

## Стратегии zapret2

Zapret Hub работает только на zapret2: Flowseal больше не поддерживается, его стратегии встроены. Если в окне задана
папка zapret2 («Настройки» → «Папка zapret2»; CLI её не меняет), `strategies list` показывает сначала встроенные
(`zapret2:general`, `zapret2:general-sni`, затем 22 копии стратегий Flowseal 1.10.3 — `zapret2:general (ALT5)`,
`zapret2:general (Flowseal)` и т.д., у них `flowseal_copy: true`), потом свои. Клон копии сохраняется под именем без
скобок, например `ALT5 copy`. Имя без префикса `zapret2:` (`"general (ALT11)"`) — ошибка, код 1.

Списки и фейки Flowseal (`%LISTS%`, `%BIN%`) лежат в папках `lists` и `bin` внутри папки zapret2: приложение кладёт
туда свои копии файлов, которых нет, и ничего не перезаписывает. Игровой фильтр (`%GameFilter*%`) — настройка
`game_filter`.

При первом запуске после версии с Flowseal приложение переносит его файлы списков и фейков в папку zapret2, игровой
фильтр — в `game_filter`. Если zapret2 готов и его служба стоит, она ставится заново с той же стратегией: в 0.8.0
её аргументы указывали на списки и фейки в папке Flowseal. Если стоит только служба Flowseal, вместо неё ставится та же
стратегия из встроенных (`general (ALT11)` → `zapret2:general (ALT11)`, неизвестная — `zapret2:general`). Итог — одно
уведомление и строка журнала. Служба `zapret` Flowseal, оставшаяся после этого, — находка `checks` с
исправлением `remove-conflicts`. Рейтинг тестов 0.8.0 с именами Flowseal `apply-best` и трей читают так же:
каждое имя — его копия в zapret2.

`zapret2 info` печатает папку, версию движка и совместимость Lua (`compat`) или ошибку (`error`).

Своя стратегия — текст аргументов `winws2` в файле: глобальная часть (`--wf-*`, `--lua-init`, `--blob`), затем
профили через `--new`. Строки, которые начинаются с `#`, — комментарии. `%LUA%`, `%FILES%`, `%LISTS%`, `%BIN%` и
`%GameFilter%`, `%GameFilterTCP%` и `%GameFilterUDP%` подставляются при проверке и установке. Текст встроенной стратегии — поле `source` в выводе
`strategies show zapret2:general`: с него удобно начать.

```
zapret-hub-cli zapret2 validate mine.txt
zapret-hub-cli zapret2 save mine mine.txt --create
zapret-hub-cli apply zapret2:mine
```

- `validate` и `save` проводят полную проверку: статическую (функции `--lua-desync`, кавычки), `winws2 --dry-run`
  и `winws2 --intercept=0`. Ошибка — код 1 с полным выводом `winws2`.
- `save` без `--create` меняет существующую стратегию. Если она активна, служба ставится заново и печатается
  итог быстрой проверки, иначе — `null`.
- Имя: 1–40 символов, латинские буквы, цифры, пробел и `-_.`, начинается с буквы или цифры; зарезервированные
  имена устройств Windows (`CON`, `NUL`, `COM1` и т. п.) отклоняются. Плохое имя — код 1 от приложения.

Удалить: `zapret-hub-cli zapret2 delete mine --yes`. Встроенные стратегии и активную удалить нельзя.

## Если приложение не запущено

Команды, которым нужно приложение, отвечают кодом 3:
``Zapret Hub is not running: start it with `zapret-hub-cli start` or run zapret-hub.exe (if it is in the tray, its CLI pipe is closed: quit it from the tray and start it again)``.

`zapret-hub-cli start` запускает задачу Планировщика «Zapret Hub». Её создаёт автозапуск приложения, и она
запускает приложение с правами администратора без запроса UAC. Потом `start` до 30 с ждёт, пока приложение
ответит, и печатает `{"app": "0.6.0"}`. Если приложение уже работает, задача не запускается: с включённым CLI
ответ приходит сразу, с выключенным — код 3 и отказ `the CLI is off: enable it in Zapret Hub → Settings`.

Если автозапуск выключен, задачи нет: `start` выходит с кодом 3 и советует запустить `zapret-hub.exe` вручную
или включить автозапуск в настройках. Запуск exe вручную требует подтверждения UAC: его делает человек.

## Ограничения

- Канал один на компьютер. Если его имя уже занято другой программой (или Zapret Hub, запущенным другим
  пользователем), приложение показывает уведомление «Канал CLI занят другой программой» и работает без CLI.
- Если канал не удалось открыть по другой причине, приложение показывает уведомление «Канал CLI не открыт», а
  если он остановился, пока приложение работало, — «Канал CLI остановлен». Оба уведомления несут текст ошибки.
  Пока канала нет, CLI отвечает, как при незапущенном приложении (код 3). `start` тут не поможет: приложение уже
  работает, задача автозапуска только откроет его окно, и через 30 с `start` выйдет с кодом 3. Выйдите из
  приложения через «Выход» в меню трея и запустите его снова.
- Канал пускает пользователя, от имени которого запущено приложение. Если в окне UAC вводили пароль другой
  учётной записи, приложение работает от неё, и CLI обычного пользователя получает отказ (код 3).
- Программа, запущенная от вашего имени, может открыть свой экземпляр канала и отвечать CLI вместо приложения:
  выполнить что-либо от имени приложения она не может, но может вернуть агенту ложный ответ.
- Итог последнего прогона (`last`) хранится в памяти приложения: после перезапуска он `null`.
- `version` печатает `"app": null` и тогда, когда приложение отказало (например, CLI выключен).

Автотесты приложение не запускают: ему нужны права администратора. Перед выпуском пройдите список вручную.

`cargo run -q -p cli --bin zapret-hub-cli -- <команда>` или `zapret-hub-cli.exe <команда>`. Код выхода —
`echo $?` в Git Bash или `$LASTEXITCODE` в PowerShell. Каждый пункт сверяется с журналом `data\logs`.

1. CLI выключен: `status` → код 3, `{"error": "the CLI is off: enable it in Zapret Hub → Settings"}`; в журнале

   `cli: get_overview: ok`.

## Ручная проверка диагностики (0.8.0)

Не входит в автотесты; выполнить с пользователем после сборки (приложение от администратора, NekoBox запущен). После
каждого пункта: служба, стратегия, маршрутизация и winws как до диагностики; в `data\logs` нет ошибок отката.

1. Голос Discord с заведомо плохой стратегией: профиль «Discord», режим «сам» → диагностика находит голосовой сервер
   (адрес и порт UDP) и путь, после которого «Подключение к RTC» проходит.
2. Dead by Daylight в поиске матча: профиль DbD, режим «со мной» → вопросы «Работает?» на каждом пути; итог называет
   адреса, которые не отвечали, и лучший путь.
3. Режим «со мной»: карточка-вопрос поверх прогресса, уведомление Windows при скрытом окне; «Да / Нет / Не знаю» ведут дальше.
4. Отмена посреди перебора: всё как было (служба, стратегия, маршрутизация), частичный итог из проверенного.
5. Падение хаба посреди перебора (завершить `zapret-hub.exe` в диспетчере задач): при следующем запуске откат по
   `data\state\pending.json` и сообщение об этом.
