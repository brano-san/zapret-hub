# Маршрутизатор на Linux — дизайн

Дата: 2026-10-25. Продолжение слияния с Linux-форком (`2026-10-24-zapret-hub-linux-merge-design.md`), где
роутер на Linux был недоступен. Пользователь: «Давай сделаем». Решения ниже — мои.

## Цель

Правила `routes.toml` (протокол, порты, подсети, домены, программы) работают на Linux так же, как на Windows:
совпавший TCP и UDP идёт через локальный SOCKS5 (SOCKS5-прокси), остальное — напрямую. Те же вкладка «Маршруты»,
команды CLI, счётчики и строки потоков (`FlowRow`, `Stats`, `ProxyState`), та же логика правил
(`rules::Table`), диагностика использует роутер как раньше (временное правило `diag-check`).

## Не цели

- IPv6 (на Windows роутер тоже только IPv4).
- Наблюдение потоков для диагностики (`observe`) на Linux — отдельная работа.
- Перехват трафика других машин (только исходящий трафик этого компьютера).

## Устройство (Linux)

Реализация `live::Live` для `cfg(target_os = "linux")` с тем же интерфейсом, что у Windows
(`open/shut/apply/proxy/stats`); `lib.rs` и всё выше не меняется.

- **Права.** Хабу нужны `CAP_NET_ADMIN` и `CAP_NET_RAW` в процессе. Кнопка «Разрешить маршрутизацию» (и
  `zapret-hub-cli routes grant`) делает один `root::Batch`: `setcap cap_net_admin,cap_net_raw+eip <exe хаба>`;
  после перезапуска хаба права есть. Без них `Live::open` возвращает ошибку с причиной и подсказкой, роутер
  в состоянии `Unavailable`. После обновления бинарника права пропадают — та же подсказка. Дочерние `nft`/`ip`
  хаб запускает с ambient capabilities (без pkexec).
- **Свои сокеты хаба** (прямые соединения и UDP-ответы) метятся `SO_MARK` (`0x2000_0000`); правила nft их
  пропускают — петли нет. Трафик прокси (SOCKS5-прокси) к его серверу не в наборах правил; на случай пересечения —
  исключение `meta skgid zapret-bypass` и порт/адрес самого SOCKS5 (loopback).
- **TCP.** Таблица `inet zapret_hub_route`, цепочка `nat output` (priority -100): для совпадающих
  (наборы IPv4-подсетей правил, наборы IP доменов, порты) — `redirect to :<acceptor>`. Правила с программами:
  перенаправляется весь TCP на портах правила; в приёмнике владелец сокета (`owner::procfs` по исходному порту)
  решает: совпало — через SOCKS5 CONNECT, нет — прямое соединение с `SO_MARK` (как `DirectReason::NoRule`).
  Исходный адрес — `getsockopt(SO_ORIGINAL_DST)`.
- **UDP.** TPROXY: в `mangle output` совпадающий UDP получает метку `0x1000_0000`; `ip rule fwmark 0x10000000
  lookup 100` + `ip route add local 0.0.0.0/0 dev lo table 100`; в `mangle prerouting` `meta mark ... tproxy to
  127.0.0.1:<udp>`. Сокет с `IP_TRANSPARENT` и `IP_RECVORIGDSTADDR`; ответ клиенту — с сокета, привязанного
  (`IP_TRANSPARENT`) к исходному адресу назначения. Через SOCKS5 UDP ASSOCIATE (уже есть в `socks.rs`); правила с
  программами — владелец по `/proc` (UDP), не совпало — прямой релей с `SO_MARK`.
- **Домены.** Ответы DNS читаются сокетом `AF_PACKET` (нужен `CAP_NET_RAW`) на всех интерфейсах, включая `lo`
  (стаб systemd-resolved `127.0.0.53` отвечает приложениям по `lo`); разбор — существующий `dns.rs`; IP
  совпавших имён добавляются в набор nft с таймаутом TTL (`Names`, как на Windows). DoT/DoH в resolved
  (`doh::resolved`) — предупреждение в UI, как сейчас.
- **Жизненный цикл.** `open`: проверка прав → сокеты приёмника → nft-таблица и ip rule/route → потоки. `apply`:
  атомарная замена наборов (`nft -f` с `flush set`), без разрыва соединений. `shut`: удаление таблицы, ip
  rule/route, закрытие сокетов. Хаб при старте удаляет оставшиеся от падения таблицу и правила.
- Чистые функции с юнит-тестами: текст ruleset из `Table` (+ наборы, порты), разбор `SO_ORIGINAL_DST`/
  `IP_RECVORIGDSTADDR` (cmsg), разбор кадров `AF_PACKET` до UDP-полезной нагрузки, решение «прокси/прямо».
  Живые тесты (нужны права, nft) — `#[ignore]`.

## Интерфейс

- «Маршруты» на Linux показывает роутер как на Windows; при отсутствии прав — карточка с причиной и кнопкой
  «Разрешить маршрутизацию». CLI: `routes grant` (Linux).
- Документация: `docs/linux.md` (раздел «Маршрутизация»), `docs/cli.md`, README, CHANGELOG (0.9.1).

## Ограничения

- Без системных изменений на машине пользователя при разработке; живые тесты — только с его разрешения.
- Лимиты сборки: Windows `CARGO_BUILD_JOBS=1`, WSL `CARGO_BUILD_JOBS=2`, одна сборка за раз.
- Windows-поведение роутера не меняется.
