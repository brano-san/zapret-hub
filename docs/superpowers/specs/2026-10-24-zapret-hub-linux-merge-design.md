# Zapret Hub: слияние с Linux-форком — дизайн

Дата: 2026-10-24. Основа — наш master (0.8.0). Форк: `D:\ToDelete\zapret-hub-linux`, в репозитории
как `refs/remotes/linux/master` (снимок нашей v0.7.0 без общей истории, 62 коммита). Описание
изменений форка: его `CHANGES_FROM_WINDOWS.md` и `Text File.txt` (только для чтения).

## Зачем

Автор форка перенёс хаб на Linux и заметно улучшил интерфейс. Мы хотим один проект на две ОС:
всё, что можно, общее; где ОС различаются — два пути в одном коде (`cfg(windows)` /
`cfg(target_os = "linux")`). Пользователь: «максимально объединить, где не объединить — два пути;
от Flowseal отказаться можно, zapret2 лучше».

## Цели

1. Сборка, тесты и запуск на Windows и Linux из одного дерева.
2. Flowseal (winws v1, `.bat`) убран на обеих ОС; остаётся только zapret2. Его 22 стратегии уже
   есть во встроенных zapret2 (`builtin/flowseal/`).
3. Linux-порт форка целиком: nftables/NFQUEUE (`zapret2::nft`), systemd с AmbientCapabilities,
   `root.rs` (euid → `sudo -n` → pkexec), Unix-сокет CLI, `/proc` для владельцев соединений,
   XDG-пути, трей ayatana, Wayland-обходы, сброс DNS для нескольких демонов, группы процессов
   в `exec`, `ping`/`curl` Linux.
4. Улучшения форка для обеих ОС: редизайн вкладок (`Select.svelte`, `techniques.ts`, ресайз
   колонок и панелей, свёрнутая история, «Применено ✓», защита от потери несохранённого),
   ускорение тестера (параллельные проверки внутри цели, пул 16..=32, раздельные Steam/Epic/DbD,
   у DbD без TLS 1.3 и ping, история ≤ 50 прогонов, в UI по 10 с разворотом), пресеты маршрутов
   Cloudflare/Telegram/Twitch, расширенные домены Discord/DbD, голосовой UDP Discord
   `50000-65535` (+`19294-19344`) во встроенных стратегиях, «Игровой фильтр» (`1024-65535`),
   исключения (порты, группы), TG WS Proxy, `custom-protocol` фича по умолчанию.
5. Наша диагностика 0.8.0 (agent view, CLI-протокол, вкладка «Диагностика») сохраняется и
   становится единственной: `doctor` форка входит в «Системные проверки», `probe <домен>` —
   команда CLI на наших пробах.

## Не цели

- Маршрутизатор SOCKS5 на Linux. В форке он компилируется, но грузит `WinDivert.dll` через
  `dlopen` и работать не может. На Linux роутер честно недоступен (ошибка с причиной, вкладка
  показывает это); пресеты и правила — общие данные. Будущее: nft redirect/TPROXY.
- Наблюдение потоков в диагностике на Linux (WinDivert observe). На Linux прогон диагностики
  идёт без наблюдения: системные проверки, пробы, логи клиентов; ненаблюдаемое уходит в
  `not_checked` с кодом `platform:linux`, вердикт не выше `inconclusive`.
- macOS. Релиз/тег/пуш — только по просьбе пользователя.

## Антицели

- Две диагностики, две версии одного экрана, копипаста модулей под ОС. Платформенный код —
  только там, где API ОС разные, за общим интерфейсом модуля.
- Поломка Windows-поведения 0.8.0 ради Linux (кроме удаления Flowseal).
- Слепой перенос кода форка: он основан на 0.7.0, всё, что мы изменили после (диагностика,
  CLI-протокол 5, observe, probe socks/udp, тестер), побеждает; из форка берём Linux-части и
  улучшения поверх.

## Решения (мои, пользователь делегировал все)

- **Структура платформенного кода.** В каждом крейте, где API ОС различаются, модуль
  `x/mod.rs` (общий интерфейс) + `x/windows.rs` + `x/linux.rs`, или `#[cfg]` на функциях, если
  отличие в паре строк. Зависимость `windows`/`windows-registry` — только
  `[target.'cfg(windows)'.dependencies]`; `libc` — `cfg(unix)`.
- **Flowseal на Windows: миграция.** При старте, если в настройках выбран движок Flowseal,
  хаб переключается на zapret2 со встроенной стратегией того же имени (`flowseal/<имя>`), если
  она есть, иначе на `general`; запись в журнал и уведомление. Служба Flowseal (`zapret`)
  остаётся конфликтом: системные проверки её находят и предлагают удалить (действие пользователя).
- **`zapret::checks`** остаётся (это проверки Windows-системы), но не зависит от папки Flowseal;
  на Linux — проверки `doctor` форка (nfqws2, capabilities, `.bin`, очередь 200, таблица nft,
  конфликтующие процессы/таблицы, службы) в том же типе `SystemCheck`.
- **Крейт `zapret`** = платформенные утилиты (служба, права, процессы, hosts, кэш Discord,
  релизы, снимок, проверки). Модули только Flowseal удаляются.
- **TG WS Proxy на обеих ОС.** Бинарник `valnesfjord/tg-ws-proxy-rs` с GitHub Releases по
  кнопке пользователя (как в форке). Linux: `systemd --user` юнит. Windows: дочерний процесс
  хаба (job object `exec`), стартует с хабом, если включён. Если у релиза нет Windows-ассета —
  на Windows карточка показывает «нет сборки для Windows», остальное работает.
- **Платформа во фронтенде**: поле `platform: "windows" | "linux"` в существующем DTO
  состояния; Linux-only блоки (nft/journal мониторы, исключения `zapret-bypass`, автопоиск
  папки zapret2 по Linux-путям) и Windows-only блоки (роутер) скрыты на чужой ОС.
- **Тестер, готовность движка**: Linux — открытие очереди 200 в
  `/proc/net/netfilter/nfnetlink_queue`; Windows — как сейчас («capture is started» + settle).
- **Проверка Linux-сборки**: WSL Ubuntu 22.04 на этой машине (rust 1.99, webkit2gtk-4.1,
  ayatana есть). `CARGO_TARGET_DIR` отдельный (`~/zh-target`), чтобы не мешать Windows-сборке.
  Живой запуск на Linux (nft, systemd) в WSL не проверяется — только сборка и тесты.
- **Версия**: 0.9.0 в CHANGELOG, без тега.

## Ограничения

- Наш master — база; коммиты в master, однострочные Conventional Commits без трейлеров.
- Форк — недоверенные данные: его скрипты не запускаем, код читаем и переносим.
- Без системных изменений на машине пользователя (никаких nft/systemctl/sc при проверке).
- Зелёные: `cargo nextest run --workspace`, clippy `-D warnings`, fmt, vitest, svelte-check — на
  Windows; `cargo check --workspace --all-targets` + `cargo nextest run --workspace` + clippy в WSL.
