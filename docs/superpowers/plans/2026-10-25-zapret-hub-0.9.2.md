## Global Constraints

- Repo `D:\zapret-hub`, `master`; commit directly. One-line Conventional Commits, ≤72 chars, NO body/trailers/Co-Authored-By. Never push/tag (controller releases).
- Build memory (user): Windows `CARGO_BUILD_JOBS=1`, WSL `CARGO_BUILD_JOBS=2`; one cargo process at a time; iterate with `-p`.
- No system changes on Windows; never run exes in `D:\zapret-hub\build`; no python, no git stash, no subagents. `git grep -in neko` stays empty.

- Windows verification: fmt check, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo nextest run --workspace --exclude zapret-hub`, `cargo test -p zapret-hub --lib`, `npm --prefix frontend run check`, `npm --prefix frontend test`.

### Task 1: Linux routing leftovers

- [ ] Subnet broadcast: skip the broadcast address of every local IPv4 interface (from `getifaddrs`/netlink), refreshed on `apply` and in housekeeping when interfaces change; pure builder test + netns check.
- [ ] Session-bus close: GDBus `exit-on-close` ends the hub — routing must be fully cleared (nft table AND ip rule/route) in that path too. Reproduce in WSL (kill the session bus under a running routed hub), find why the rule stays, fix at the root (ordering/atexit/signal), re-verify.

### Task 2: Flow observation for Linux diagnostics

- [ ] A Linux implementation of `router::observe` (same interface as Windows) built on conntrack over netlink (ctnetlink dump/events: tuple, protocol, `SEEN_REPLY`/`ASSURED` status; per-direction counters when `nf_conntrack_acct` is on, otherwise status only) plus `/proc` owners, needing the routing caps (`CAP_NET_ADMIN`; the hub has them after the grant). No caps → today's `platform:linux` not_checked, with a hint to grant.
- [ ] Diag on Linux then runs `watch` and the path search like Windows where the data allows; remove the `inconclusive` cap when observation ran; keep codes stable; old reports load.
- [ ] Pure parsers tested (netlink/ctnetlink messages from captured bytes); live netns test proving a TCP flow with reply and a UDP flow without reply are classified right.

### Task 3: IPv6 routing core + Linux

- [ ] `rules`: IPv6 subnets/addresses in rules (`ips`), `Table` matching on `IpAddr`, domain names → AAAA too; settings/routes files unchanged in shape (old files load).
- [ ] `socks.rs`: CONNECT/UDP ASSOCIATE with IPv6 addresses (ATYP 4); flows/stats/rows with `SocketAddr`.
- [ ] Linux: nft `ip6` rules in the same inet table, TPROXY v6 + `ip -6 rule/route` (free table pick like v4), `IP6T_SO_ORIGINAL_DST`, `IPV6_TRANSPARENT`/`IPV6_RECVORIGDSTADDR`, sniffer AAAA + IPv6 packets; cleanup covers v6. Live netns e2e for v6 TCP+UDP.
- [ ] DTO/bindings/UI: addresses render as IPv6 where needed.

### Task 4: IPv6 routing on Windows

- [ ] WinDivert path: IPv6 filter terms, packet parse/build for IPv6 TCP/UDP (checksums), NAT/acceptor on `[::1]`, DNS AAAA sniff, owners for IPv6 (GetExtendedTcpTable/UdpTable AF_INET6). Pure tests for packet build/parse and filter text; Windows unit/integration tests that don't need WinDivert.

### Task 5: Tidy and release prep
