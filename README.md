# Zapret Hub

Приложение в трее для [bol-van/zapret2](https://github.com/bol-van/zapret2) на Windows и Linux: выбирает и
переключает стратегии, тестирует их и ставит лучшую, ведёт службу движка, прокси и диагностику.
Windows — `winws2.exe` и WinDivert, Linux — `nfqws2` и nftables (подробнее — [docs/linux.md](docs/linux.md)).

## Что умеет

- **Обзор:** состояние обхода («Обход работает / выключен») с действиями, стратегия, быстрая проверка, версия
  движка, прокси SOCKS5, TG WS Proxy, лучшая стратегия последнего теста.
- **Стратегии:** встроенные и свои стратегии zapret2, фильтр по технике обхода, сводка по сервисам, редактор
  аргументов, конструктор circular, применение в один клик.
- **Тесты:** HTTP, TLS 1.2, TLS 1.3, пинг и набор DPI. Цели проверяются разом, живой прогресс, рейтинг с
  отдельными колонками Steam, Epic и Dead by Daylight, история (последние 50 прогонов), копирование результатов.
- **Инструменты:** служба (запуск, остановка, перезапуск, удаление), системные проверки, TG WS Proxy, hosts,
  очистка кэша Discord, сброс DNS; на Linux ещё монитор nftables и журнал службы.
- **Исключения:** домены, подсети и порты, которые обход не трогает (`list-exclude-user.txt`,
  `ipset-exclude-user.txt`; порты — на Linux в таблице nft).
- **Диагностика:** наблюдает за программой или профилем и подбирает путь обхода (на Linux — через conntrack,
  с правами маршрутизации, см. `docs/linux.md`).
- **Маршруты:** выбранный трафик идёт через SOCKS5 по домену, подсети или программе; пресеты
  Discord, Dead by Daylight, Cloudflare, Telegram и Twitch.
- **TG WS Proxy:** локальный MTProto-прокси [tg-ws-proxy-rs](https://github.com/valnesfjord/tg-ws-proxy-rs):
  скачивается и запускается из хаба (на Linux — пользовательский юнит systemd).
- **Трей:** цвет иконки показывает состояние, меню переключает на стратегии из первой пятёрки рейтинга, быстрая
  проверка раз в 30 минут, уведомления.
- **Командная строка:** `zapret-hub-cli` для ИИ-агентов и скриптов — те же действия, что в окне, кроме смены
  папки zapret2, вывод в JSON; плюс `probe`, `service`, `nft`, `dns-flush`, `exclusions`, `tg-ws`.
  Включается в настройках.

Стратегии и службы Flowseal убраны в 0.9.0: встроенные стратегии zapret2 включают копии стратегий Flowseal 1.10.3.
Настройки 0.8.0 с Flowseal переносятся на zapret2 сами при первом запуске.

## Как выбирается лучшая стратегия

Стандартный набор: выше та, у которой меньше неудачных проверок; при равенстве — меньше медианная задержка
удачных проверок (HTTP, TLS 1.2, TLS 1.3). Набор DPI: выше та, у которой меньше проверок с признаком
блокировки, затем меньше неудачных. ICMP-пинг показан отдельным столбцом и на порядок не влияет. Стратегия,
которая не запустилась, — в конце.

## Что нужно

**Windows:** Windows 10 1803 или новее, либо Windows 11, x64 (`curl.exe` входит в Windows начиная с 1803);
права администратора (служба и WinDivert); WebView2 Runtime (в Windows 10 и 11 обычно уже есть).

**Linux:** x86_64 с systemd. Пакеты: `webkit2gtk-4.1`, `gtk3`, `libayatana-appindicator3`, `nftables`, `curl`,
`iputils` (`ping`), `polkit`. Права root хаб просит сам, только на нужные действия (см. «Linux» ниже).

Нужен релиз [bol-van/zapret2](https://github.com/bol-van/zapret2): его можно скачать кнопкой «Скачать последний
релиз…» в мастере и в «Настройках» (раздел «Скачать движок» ниже) или указать готовую папку.

## Установка и запуск

### Windows

Архив `zapret-hub-<версия>.zip` — на странице [релизов](https://github.com/brano-san/zapret-hub/releases).

1. Распакуйте архив в отдельную папку, например `C:\Tools\ZapretHub`. Настройки и данные лежат рядом с exe.
   С автозапуском берите папку, куда без прав администратора не записать, например внутри `C:\Program Files\`:
   задача автозапуска запускает exe с наивысшими правами без запроса UAC, а exe в папке, открытой для записи
   (как `C:\Tools\…`), может подменить любая программа. То же касается включённого TG WS Proxy: хаб с правами
   администратора запускает `data\tg-ws-proxy\tg-ws-proxy.exe` при каждом старте, так что папка хаба должна быть
   закрыта для записи и без автозапуска.
2. Запустите `zapret-hub.exe` и подтвердите запрос UAC.
3. Мастер первого запуска спрашивает папку zapret2 (найдёт её или даст выбрать вручную, либо скачает с GitHub).
   Затем предложит прокси SOCKS5, если тот сейчас отвечает, и спросит про автозапуск.

Крестик прячет окно в трей, выход — «Выход» в меню трея. Повторный запуск exe открывает уже работающую копию.

### Linux

Подробности, устройство и разбор неполадок — в [docs/linux.md](docs/linux.md). Кратко:

1. Поставьте пакеты (Debian/Ubuntu: `libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev nftables
   curl iputils-ping policykit-1`; Arch: `webkit2gtk-4.1 gtk3 libayatana-appindicator nftables curl iputils
   polkit`) и соберите приложение (раздел «Сборка из исходников»). Запускайте от обычного пользователя.
2. Группа `zapret-bypass`: процесс, запущенный через `sg zapret-bypass "<команда>"`, идёт мимо обхода.
   `sudo groupadd -f zapret-bypass && sudo usermod -aG zapret-bypass $USER`, затем перезайдите в сессию.
3. Служба `zapret2.service` ставится в `/etc/systemd/system` и работает от вашего пользователя с
   `CAP_NET_ADMIN`/`CAP_NET_RAW`; таблица nftables `inet zapret_hub` направляет пакеты в очередь 200.
4. Root: хаб пробует `sudo -n`, затем `pkexec` (один запрос пароля на «Применить»). Чтобы запросов не было,
   добавьте правило `sudoers` или polkit для своего пользователя (пример и оговорки — в `docs/linux.md`); хаб
   таких правил сам не ставит.
5. Маршрутизация через SOCKS5: кнопка «Разрешить маршрутизацию» на вкладке «Маршруты» (или
   `zapret-hub-cli routes grant`) копирует хаб и `zapret-hub-cli` в `/usr/local/lib/zapret-hub/` и выдаёт
   `CAP_NET_ADMIN`/`CAP_NET_RAW` копии `zapret-hub-cli` для вас одного; хаб запускает себя через неё. Затем
   перезапустите хаб; после обновления — снова. IPv4 и IPv6 (раздел «Маршрутизация» в `docs/linux.md`).

## Где данные

Всё рядом с exe:

- `zapret-hub.toml` — настройки;
- `data\strategies\` — свои стратегии;
- `<папка zapret2>\strategies\` — свои стратегии zapret2, по файлу `<имя>.txt`: лежат у движка и переживают обновление приложения, старые из `data\zapret2` переносятся при первом запуске;
- `data\routes.toml` — правила маршрутизации через SOCKS5;
- `data\diag\` — отчёты диагностики, последние 20;
- `data\tests\` — результаты тестов, `data\cache\` — набор DPI;
- `data\logs\ГГГГ-ММ-ДД.log` — журнал: каждая команда (`sc`, `net`, `curl.exe`, `winws2.exe` и другие) с кодом выхода
  и полным выводом;
- `data\state\pending.json` — снимок на время изменяющей операции. Если приложение закрылось посреди неё, при
  следующем запуске оно вернёт службу zapret2 и winws2 как было и скажет об этом;
- `data\webview\` — данные окна.

## Что приложение меняет в системе

- Службу `zapret2` и имя стратегии в реестре на её ключе, когда применена стратегия (на Linux — юнит
  `zapret2.service` и таблицу nftables, см. `docs/linux.md`). Старую службу `zapret` (Flowseal) применение
  не трогает: её удаляет разовый переход с 0.8.0 и кнопка системной проверки «Удалить службы».
- Файлы в папке zapret2: недостающие списки и фейки (`lists`, `bin`; существующие не перезаписываются),
  исключения (`lists`), свои стратегии (`strategies`).
- `hosts` — только по кнопке «Обновить hosts» и после подтверждения: блок между строками `# zapret-hub begin`
  и `# zapret-hub end`.
- Задачу Планировщика «Zapret Hub», если включён автозапуск.
- Ключ `HKCU\Software\Classes\AppUserModelId\ZapretHub` — имя приложения в уведомлениях.
- Именованный канал `\\.\pipe\zapret-hub-cli`, пока приложение работает. Команды через него выполняются, только
  если в настройках включено «Управление из командной строки».
- Глобальную настройку TCP: при каждой установке службы и по кнопке системной проверки —
  `netsh interface tcp set global timestamps=enabled`. Она действует на всю систему и остаётся после удаления
  приложения; если до этого она была выключена (так по умолчанию в Windows), вернуть:
  `netsh interface tcp set global timestamps=disabled`.
- Перед записью `hosts` его прежний текст сохраняется рядом, в `hosts.zapret-hub.bak`.
- Кнопки системных проверок удаляют службы GoodbyeDPI, discordfix_zapret, winws1, winws2, WinDivert и
  WinDivert14, а также старую службу `zapret` (Flowseal), если она осталась. На Linux `zapret` — юнит
  bol-van/zapret: его хаб только останавливает, но не отключает и не удаляет.
- Дескрипторы WinDivert из папки движка, пока маршрутизация включена: драйвер движка, своего хаб ничего не
  ставит. Закрытие хаба закрывает дескрипторы, и трафик идёт как был.
- Очистка кэша Discord закрывает Discord и удаляет его папки `Cache`, `Code Cache` и `GPUCache`.

## Диагностика

Вкладка «Диагностика» (и `diag` в CLI): выберите профиль (Discord, Dead by Daylight, YouTube, Steam, Discord: демонстрация экрана) или программу и нажмите
«Начать». Хаб 30 с наблюдает за соединениями программы, находит адреса, на которых нет ответа, пробует для каждого пути
обхода (напрямую, zapret2 со стратегиями, прокси точечно, прокси вместе со zapret), возвращает всё как было и
показывает итог: что не так, лучший путь и кнопку «Применить». Перед применением хаб перепроверяет остальные профили и
предупреждает о поломках.

- Режим «сам»: хаб оценивает путь своими пробами. Режим «со мной»: на каждом пути хаб спрашивает, работает ли голос или
  матч, и вы отвечаете «Да / Нет / Не знаю».
- Откат: при отмене, ошибке и падении хаба всё возвращается как было (при падении — при следующем запуске, по
  `data\state\pending.json`).
- Из чужих файлов хаб только читает журналы Discord и Steam и ничего в них не меняет.
- Отчёты — `data\diag\<дата-время>.json`, хранятся последние 20.

## Тесты стратегий

На время прогона служба zapret2 останавливается, а `winws2` (на Linux `nfqws2` с таблицей nftables на весь прогон)
по очереди запускается с каждой выбранной стратегией; после прогона служба возвращается как была. Цели
проверяются разом: стандартный набор занимает около 15 секунд на стратегию. Прогон можно отменить; закрытие окна
его не прерывает. В истории остаются 50 последних прогонов.

## Скачать движок

В мастере и в «Настройках» (под папкой zapret2) есть кнопка «Скачать последний релиз…». Выберите, куда
скачать (по умолчанию — папка над папкой приложения, а на Windows, если в её пути есть пробелы или кириллица, —
корень системного диска), и нажмите «Скачать».

- Источник — последний релиз [bol-van/zapret2](https://github.com/bol-van/zapret2/releases)
  (`zapret2-<версия>.zip`). Адрес берётся из GitHub API, качает системный `curl`; если напрямую не вышло, —
  через прокси из настроек. Ход загрузки виден, её можно отменить.
- Релиз распаковывается в новую папку `<куда>\zapret2-<версия>`. Если такая папка уже есть и не пустая,
  загрузка отказывается.
- Проверка: каждый файл `binaries\<система>\*` и `lua\*` сверяется с `sha256sum.txt` релиза; при несовпадении
  папка удаляется.
- Защитник Windows часто удаляет эти архивы и `winws2`. Тогда приложение скажет об этом и оставит пустую папку:
  добавьте её в исключения (Безопасность Windows → Защита от вирусов и угроз → Управление настройками →
  Исключения) и скачайте снова. Само приложение исключений не добавляет.
- Скачанная папка подставляется в поле и проверяется; сохраняет её, как и выбранную вручную, «Далее» в мастере
  или «Сохранить» в настройках. Из `zapret-hub-cli` скачать нельзя. «Найти автоматически» ищет уже скачанный
  движок по обычным путям своей системы.

## zapret2

[bol-van/zapret2](https://github.com/bol-van/zapret2) — следующий движок автора zapret: `winws2.exe` (Linux:
`nfqws2`) и стратегии на Lua. Скачайте релиз со [страницы релизов](https://github.com/bol-van/zapret2/releases),
распакуйте в папку без кириллицы в пути (например, `D:\zapret2`) и укажите её в «Настройках» → «Папка zapret2».
Подходит и zapret-win-bundle. Приложение проверит файлы и покажет версию движка или ошибку, если `lua\` не
подходит к движку.

- Встроенные стратегии:
  - `general` и `general-sni` — по примеру из документации zapret2 (bol-van);
  - 22 копии стратегий Flowseal 1.10.3 (MIT), перенесённые на `winws2`: `general (ALT5)`,
    `general (FAKE TLS AUTO)` и т.д.; `general.bat` Flowseal — `general (Flowseal)`. Копии фиксированные
    (обновляются новым выпуском хаба), в шапке каждой — источник и что изменено при переносе. В прогон тестов
    по умолчанию копии не входят — выбирайте их вручную. Клон копии получает имя без скобок: `ALT5 copy`.
  Подберите лучшую тестом.
- Свои стратегии — текст аргументов `winws2` в редакторе: «Клонировать» у встроенной, затем «Проверить» и
  «Сохранить». Проверка — статическая, `winws2 --dry-run` и `winws2 --intercept=0`. Фильтр по технике в
  списке стратегий находит стратегии с `fake`, `multisplit`, `circular` и т.д.
- Списки (`list-general-user.txt` и др.) и фейки общие и лежат в папке zapret2 (`lists`, `bin`).
  Недостающий `list-general-user.txt` хаб создаёт со своим набором доменов (AWS, X/Twitter, Cloudflare, серверы и
  сайт DbD, NuGet); существующий не трогает. Набор — `crates/zapret2/src/files/lists/list-general-user.txt`.
- Каждая встроенная стратегия берёт UDP голоса Discord до порта 65535 (`50000-65535`).
- **circular** — оркестратор zapret2, который перебирает варианты обхода отдельно для каждого сайта: после
  нескольких неудач (`fails`, по умолчанию 3; неудача — ретрансмиссии, RST или редирект от DPI) переходит к
  следующему варианту и запоминает его. Карточка стратегии показывает circular-профили по-человечески:
  фильтр, `fails`/`retrans` и пронумерованные варианты («1: fake tls_google ×8 + multisplit 1 seqovl»,
  «2: multidisorder midsld», финальный отмечен). В редакторе кнопка «Circular…» открывает конструктор:
  выберите профиль (его инстансы станут вариантом 1) или новый (TCP-порты, протокол, список), добавляйте,
  переставляйте и удаляйте варианты (готовые: fake TLS google, fake stun2, multisplit seqovl, multidisorder
  midsld, fakedsplit — или свой текст), задайте `fails`/`retrans` и финальный вариант, затем «Записать в
  текст». Конструктор пишет `--out-range=-s34228`, `--in-range=-s5556 --lua-desync=circular`,
  `--in-range=x` и метки `strategy=N`, а недостающие блобы `tls_google`/`stun2` добавляет в глобальную
  часть; главным остаётся текст. Статическая проверка не пропустит дыры в номерах `strategy=`, `strategy=`
  без circular и circular без вариантов, а без `--in-range` перед circular предупредит.
- «Сделать circular из стратегий…» (кнопка над списком) объединяет 2–5 стратегий zapret2: профили с
  одинаковым фильтром, которые есть во всех и различаются инстансами, становятся circular с вариантом на
  каждую стратегию в порядке выбора. Остальное берётся из первой. Предпросмотр объясняет каждый профиль
  (UDP-профили не объединяются: circular считает неудачи по TCP), затем текст открывается в редакторе для
  проверки и сохранения. ALT11 и ALT11 plus отличаются только профилем игровых сервисов, так что circular из
  них не получится — нужны стратегии с разными инстансами.
- Папку zapret2 меняют только в окне: `zapret-hub-cli` её не меняет.
- «Применить» на стратегии ставит службу `zapret2`. Старую службу `zapret` (Flowseal) оно не трогает: системная
  проверка назовёт её конфликтом и предложит «Удалить службы».

## Маршрутизация через SOCKS5

Выбранный трафик идёт через локальный SOCKS5-прокси прямо из процесса хаба: без TUN и без окна PowerShell.
UDP — через `UDP ASSOCIATE`, TCP — через `CONNECT`; цель правила — подсеть IPv4 или IPv6, домен или программа. Это замена
`E:\Zapret\utils\discord-udp-proxy.ps1`: на время работы маршрутизации этот скрипт нужно закрыть.

На Linux маршрутизация работает через nftables и TPROXY (`setcap` и ограничения — в `docs/linux.md`), правила
лежат в `~/.local/share/zapret-hub/routes.toml`, программы пишутся без `.exe`.

Как включить:

1. «Настройки» → адрес SOCKS5, например `127.0.0.1:2080`. Прокси должен принимать UDP (SOCKS5 UDP
   ASSOCIATE). Авторизация не поддерживается. Прокси должен быть на этом компьютере (`127.x.x.x`): с адресом в
   локальной сети маршрутизация не включается и пишет почему.
2. Вкладка «Маршруты» → «Добавить из профиля» → «Discord голос» (UDP, голос), «Discord целиком» (UDP и TCP
   по доменам `discord.com`, `discord.gg`, `discordapp.com`, `discordapp.net`, `discord.media`) или
   «Dead by Daylight» (UDP и TCP, программа `DeadByDaylight-Win64-Shipping.exe` и домен `bhvrdbd.com`).
3. Переключатель «Маршрутизация» (или пункт «Маршрутизация: вкл/выкл» в меню трея, или `zapret-hub-cli router on`). Флаг
   `router_enabled` сохраняется: при следующем запуске маршрутизация включится сама.

Правила лежат в `data\routes.toml`. Файл можно править руками (Блокнот, BOM и CRLF читаются): хаб проверяет его
время записи раз в 2 с и перечитывает при изменении. Битый файл не стирается и не применяется: работающие
правила остаются прежними, а вкладка показывает ошибку с номером строки.

```toml
[[rule]]
name = "Discord целиком"
enabled = true
protocol = "both"                        # "tcp" | "udp" | "both"
ports = []                               # пусто или нет поля = все порты; иначе ["443", "50000-65535"]
ips = ["104.29.0.0/16"]                  # адрес или подсеть: a.b.c.d/n, 2001:db8::/32
domains = ["discord.com", "discord.gg"]  # домен и все его поддомены
apps = ["Discord.exe"]                   # имя .exe или полный путь в одинарных кавычках: 'C:\Games\game.exe'
```

- Имя: 1–40 символов (латиница, кириллица, цифры, пробел, `-_.`), начинается с буквы или цифры, уникально без учёта регистра.
- `protocol` обязателен: `"tcp"`, `"udp"` или `"both"`. Хотя бы одна цель: `ips`, `domains` или `apps`.
- Порты: `1–65535` или диапазон `a-b`, `a ≤ b`.
- Домен: без схемы и пути, не меньше двух меток из латиницы, цифр и `-`, регистр не важен.
- `apps`: имя файла (без `\`, `/` и `:*?"<>|`) или абсолютный путь (`C:\…`, `\\server\share\…`), в обоих случаях
  оканчивается на `.exe` без учёта регистра; иначе ошибка «is not a program» с номером строки.
- Соединение или поток идёт в прокси, если совпало хотя бы одно включённое правило: протокол, порт и цель.
- Подсетей в фильтре WinDivert не больше 64 диапазонов (IPv4 и IPv6 вместе): сверх этого ближайшие диапазоны
  сливаются (сначала IPv6, потом IPv4), и фильтр шире правил. Хаб сверяет совпадение сам и лишнее отправляет без изменений, но через хаб идёт больше пакетов. Предел:
  слитый диапазон правила без портов (например, «Discord целиком») может направить через хаб весь трафик к
  широкому диапазону: нагрузка на процессор и задержка при долгой работе.
  Если фильтр не влез и после слияний, ошибка правил — «too many rules for the capture filter»: выключите или
  сузьте часть правил.
- Multicast (IPv4 и IPv6), broadcast и DHCP (с адреса `0.0.0.0` или `::`) в прокси не уходят никогда.

IPv6:

- Подсети и адреса IPv6 в `ips`, ответы AAAA для доменов; прокси получает адрес IPv6 в `CONNECT` и в
  заголовке UDP. У прокси должен быть выход в IPv6. Если его нет: TCP — прокси отказал в `CONNECT`, адрес на
  60 с идёт напрямую (как ниже); UDP — если через прокси ушло 3 датаграммы и за 3 с не пришло ни одного ответа,
  поток переходит на прямой путь, а новые потоки UDP к этому адресу 60 с идут напрямую (строка «Потоки»: «no answer
  through the proxy over IPv6»). IPv4 так не переключается.
- Пакеты IPv6 читаются и с заголовками расширений hop-by-hop, routing, destination options и первого фрагмента;
  с другими (и фрагменты UDP) идут без изменений.

Домены и TCP:

- Домены узнаются из ответов DNS: хаб подсматривает их по UDP-порту 53 и запоминает адреса домена на срок
  TTL, но не меньше 5 минут и не больше суток. Если браузер или программа использует «безопасный DNS» (DNS по HTTPS) или DNS по
  TLS, ответов хаб не видит: выключите «безопасный DNS» в браузере или добавьте подсети в `ips`. То же при зашифрованном DNS в самой Windows («Параметры» → «Сеть и Интернет» → свойства адаптера → «Шифрование DNS»): системные запросы идут по HTTPS, и правила по доменам не срабатывают ни для одной программы; хаб видит это по реестру и предупреждает на вкладке «Маршруты».
- TCP перенаправляется в локальный приёмник хаба на `0.0.0.0` и `[::]` (один порт на сеанс маршрутизации; если
  IPv6-приёмник не открылся, IPv6-соединения идут напрямую), а тот делает `CONNECT` к прокси. При первом включении Windows может спросить про брандмауэр для `zapret-hub.exe`:
  разрешите доступ. Хаб правил брандмауэра не добавляет и не меняет. Если соединение к приёмнику заблокировано,
  через 2 с адрес на 60 с уходит напрямую, а во вкладке «Потоки» строка «напрямую: брандмауэр Windows не
  пропустил соединение к хабу».
- Соединения, открытые до включения маршрутизации или до появления правила (например, уже запущенный Discord),
  идут как были; через прокси пойдут новые соединения, то есть после перезапуска программы.
- SYN, отправленный раньше, чем хаб разобрал ответ DNS с этим адресом, может уйти напрямую.
- Поток UDP, начавшийся в момент смены фильтра перехвата, может посреди потока перейти с прямого пути на прокси
  (QUIC при этом откатывается на TCP).
- Адрес помнит последний домен, под которым его видел DNS: `CONNECT` и заголовок UDP к прокси несут этот домен.
- Прокси отказал в `CONNECT` или не ответил за 3 с: клиент получает RST, а адрес на 60 с идёт напрямую. Когда
  прокси вернулся после недоступности, эти пометки снимаются.
- Пауза (тест стратегий, смена движка) и выключение маршрутизации обрывают перенаправленные TCP-соединения: программа
  переподключается. Полузакрытое соединение живёт, пока не пройдёт 120 с без пакетов.
- Правило выключено или запись DNS истекла посреди соединения: открытое соединение остаётся как было. Адрес
  живого потока UDP не истекает, пока поток жив.
- Таблица «адрес → домен» живёт в хабе и переживает паузы.

Программы:

- Совпадение без учёта регистра: элемент с `\` — полный путь к exe, иначе — имя файла exe. Правило с
  `apps` совпадает и по `ips`/`domains`: достаточно любой цели.
- TCP решается на первом SYN соединения, UDP — на первом пакете потока. Программа, запущенная до включения
  маршрутизации (например, игра посреди матча), узнаётся по таблицам Windows.
- Пока запущена программа из UDP-правила, через хаб идёт весь исходящий UDP на портах правила (чужие пакеты
  уходят дальше без изменений), поэтому лучше указать порты. Пока программа не запущена, UDP не
  перехватывается; TCP — только первые SYN.
- Браузер в `apps` заставляет хаб пересобирать фильтр на каждый новый адрес назначения.
- Первые пакеты UDP программы, чей первый сокет — UDP и открыт раньше, чем пересобрался фильтр, могут уйти
  напрямую.
- Потоки без правила, пойманные ради правил по программе, видны во вкладке «Потоки» при «все» (не больше
  500 строк, в итоги не входят).

Что важно знать:

- Прокси не отвечает две проверки подряд (проверка раз в 10 с) — новые потоки и соединения идут напрямую, в шапке
  вкладки и в подсказке значка трея «прокси недоступен, трафик идёт напрямую», на значке — красная точка. Когда
  прокси вернулся, через него снова идут новые потоки и те, что ушли напрямую из-за его отказа (звонок продолжается
  через прокси).
- На время прогона тестов стратегий и смены движка маршрутизация встаёт на паузу и потом возобновляется.
- WinDivert берётся из папки запущенного `winws2.exe` (рядом с ним); ничего не запущено — из папки zapret2.
  Своего драйвера хаб не ставит.
- Пока маршрутизация включена, хаб держит драйвер WinDivert загруженным. Поэтому системная проверка
  «осиротевший драйвер WinDivert» показывается пройденной, а «Удалить службу» и «Удалить службы» (удаление
  драйвера) на время своей работы ставят маршрутизацию на паузу.
- Однажды включённая маршрутизация держит `WinDivert.dll` движка загруженной (файл занят), пока хаб не закрыт.
  Чтобы распаковать обновление zapret2 поверх папки, закройте хаб.
- Трафик самого хаба и процесса, слушающего порт прокси, не перехватывается (защита от петли через VPN).

Команды CLI: `router on|off|status`, `routes list|show|add|edit|enable|disable|remove|preset|flows|grant`, см.
`docs/cli.md`.

## Командная строка для агентов

`zapret-hub-cli.exe` лежит рядом с `zapret-hub.exe` и передаёт команды работающему приложению: ИИ-агент
(Claude Code и другие) или скрипт смотрит состояние, применяет стратегии, меняет списки и флаги, запускает тесты
и читает рейтинг. Вывод — JSON, коды выхода постоянные, прав администратора CLI не просит.

По умолчанию CLI выключен: включите «Управление из командной строки» в настройках. После этого любая
программа, запущенная от вашего имени, сможет менять zapret через приложение, а со zapret2 запускать код от
администратора и SYSTEM (см. раздел «Как включить» в `docs/cli.md`). Проверка: `zapret-hub-cli status`.

Подобрать и применить лучшую стратегию:

```
zapret-hub-cli tests run --wait
zapret-hub-cli apply-best
zapret-hub-cli quick-check
```

Все команды, коды выхода и рецепты — в `cli.md` рядом с exe (в исходниках — `docs/cli.md`) и в
`zapret-hub-cli --help`.

## Антивирусы

Приложение запускает `winws2.exe` (Linux: `nfqws2`), управляет службой zapret2 и может править `hosts`, поэтому антивирус может счесть
его подозрительным. Своего WinDivert в приложении нет: драйвер берётся из папки zapret2. Если exe попал в
карантин, добавьте папку приложения в исключения.

## Если что-то не работает

Текст любой ошибки копируется кнопкой «Копировать» в уведомлении; подробности — в журнале `data\logs`.
Системные проверки на вкладке «Инструменты» диагностируют службу, драйвер и конфликтующие обходы.

## Удаление

1. Выключите автозапуск в настройках (или `schtasks /Delete /TN "Zapret Hub" /F`).
2. Выйдите из приложения через трей и удалите его папку.
3. По желанию удалите ключ уведомлений: `reg delete HKCU\Software\Classes\AppUserModelId\ZapretHub /f`.

Служба zapret2 и папка zapret2 остаются. Службу удаляет кнопка на вкладке «Инструменты».

На Linux остаются юнит `/etc/systemd/system/zapret2.service` и `/etc/zapret-hub/` (удалите вручную после `systemctl disable --now zapret2`), `~/.config/zapret-hub`, `~/.local/share/zapret-hub`.

На Windows остаются блок между
`# zapret-hub begin` и `# zapret-hub end` в `C:\Windows\System32\drivers\etc\hosts` (удаляется в редакторе,
запущенном от администратора) вместе с копией `hosts.zapret-hub.bak` и настройка TCP timestamps (см. выше).

## Сборка из исходников

Нужны Rust (версию задаёт `rust-toolchain.toml`), Node.js 24 LTS и на Windows Microsoft C++ Build Tools, на Linux
пакеты из раздела «Установка и запуск» и `build-essential`/`base-devel`.

```
npm install
npm run tauri build
```

На Linux бинарники — `target/release/zapret-hub` и `target/release/zapret-hub-cli`, `npm run tauri dev` — от обычного
пользователя. Готовый exe на Windows — `target\release\zapret-hub.exe`. CLI — отдельный пакет: `cargo build --release -p cli` собирает
`target\release\zapret-hub-cli.exe`.
`powershell -NoProfile -ExecutionPolicy Bypass -File tools\package.ps1` собирает оба exe и кладёт в
`dist\zapret-hub-<версия>.zip` вместе с README и `cli.md`. `npm run tauri dev` запускается из терминала с правами
администратора; сборка, тесты, `npm run check` и `zapret-hub-cli` — из обычного.

Выпуск: поднять версию в `Cargo.toml` и `package.json`, раздел версии в `CHANGELOG.md`, затем тег `v<версия>`
(`git tag v0.7.0 && git push origin v0.7.0`). CI (`.github/workflows/release.yml`) прогоняет тесты, собирает zip
и создаёт релиз с этим разделом CHANGELOG. Ручной запуск в Actions только собирает zip (артефакт).
